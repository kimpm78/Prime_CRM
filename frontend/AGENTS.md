# フロントエンド向けエージェント指示

## アーキテクチャと規約

- 本指示は、`frontend/` 配下のファイルに対してリポジトリルートの `AGENTS.md` を補足する。
- プロジェクトですでに採用しているVue 3 Composition API、TypeScript、Vite、Pinia、Vue Router、PrimeVue / Volt UI、Tailwind CSS 4、Lucideアイコンを使用する。
- TypeScriptの厳密な型を維持する。型エラーを回避するために `any`、安全でない型アサーション、重複したAPIインターフェースを使用せず、実際のAPI契約を `src/types` に定義する。
- 既存のコンポーネント境界に従う。
  - `components/ui`: CRM固有の業務ロジックを含まない、ソース管理されたVolt UIプリミティブ。
  - `components/atoms`: 最小単位の再利用可能なアプリケーションコントロール。
  - `components/molecules`: Atomを組み合わせた小規模なUI。
  - `components/organisms`: CRM業務単位のUIセクション。
  - `views`: ルーティング、データ取得、ページ構成。
- ネットワークアクセスは `src/services`、共有するサーバー状態はPinia Storeに配置する。コンポーネント内に場当たり的な `fetch` 呼び出しを分散させない。
- 単発の色、余白、コントロール、操作パターンを追加する前に、既存のデザイントークンとコンポーネントを再利用する。

## UX、文言、アクセシビリティ

- ユーザー向け文言は自然な日本語で記述し、既存のCRM用語を一貫して使用する。
- データ連動画面を変更する際は、読み込み中、データなし、エラー、成功、無効状態を維持する。
- セマンティックHTML、入力項目に関連付けたラベル、キーボード操作可能なコントロール、視認できるフォーカス状態、アイコンのみの操作に対する意味のあるアクセシブルネームを使用する。
- 状態や意味を色だけで表現しない。既存のモバイル最小幅と一般的なデスクトップ幅で利用できるレイアウトを維持する。
- 絵文字や無関係なアイコンライブラリを追加せず、プロジェクト既存の実装パターンを通じてLucideアイコンを使用する。

## APIと状態管理

- `src/services/api.ts`、Pinia Store、`src/types` を、バックエンドのレスポンス形式およびバリデーションエラーと一致させる。
- リクエスト失敗を隠さない。開発者にとって安全な診断情報を保持しつつ、ユーザーに役立つ日本語のエラー状態を表示する。
- 更新処理後の重複リクエストと古いUI状態を避ける。影響を受けるStoreデータを意図的に更新または再取得する。
- 公開設定はViteの環境変数から読み込む。フロントエンドコードに秘密情報を埋め込まない。すべての `VITE_*` 値はビルド時に公開されるものとして扱う。

## Storybookと品質確認

- 再利用可能なAtom、Molecule、Organismを新規作成または大きく変更する場合は、Storybook Storyを追加または更新する。正常状態だけでなく、意味のある表示状態を対象にする。
- `frontend/` から最低限、次のコマンドを実行する。

```bash
npm run type-check
npm run build
```

- 再利用可能なコンポーネントを変更した場合は、次のコマンドも実行する。

```bash
npm run build-storybook
```

- 依存パッケージがDocker内にのみインストールされている場合は、リポジトリルートから `docker compose exec frontend` を付けた同等のコマンドを実行する。
- 環境が許す場合は、大きなレイアウト変更や操作変更をアプリケーションまたはStorybookで目視確認する。
